# ХабИндекс

Инструмент для кейса **А2 «Индекс транспортной связанности»** (трек «Хабы», хакатон МАИ).
Оценивает связанность пар городов и потенциал каждого города как пересадочного узла, сравнивает сценарии улучшения связи и показывает, какое улучшение рассмотреть первым.

> **Статус данных.** В переданных материалах есть только каталог источников организаторов, без таблиц маршрутов и населения.
> Поэтому все числа в `outputs/` — на **синтетических** данных (учебный пример и демо-выборка).
> Для реальных выводов загрузите таблицы организаторов (см. `data/README.md`) и пересчитайте.

## Что считает

**Связанность пары городов** (0–100):

```
S_ij = 100 · (0,7 · T_ij + 0,3 · M_ij)
T_ij = min(1; 6 / t_ij)      t_ij — минимальное время по доступным видам транспорта, ч
M_ij = min(1; m_ij / 3)      m_ij — число видов транспорта (авто, ЖД, авиа)
нет связи → S_ij = 0
```

**Потенциал города h как хаба** (0–100):

```
H_h = Σ (P_i^a · S_ih) / Σ P_i^a,   i ≠ h
```
`P_i` — население города-отправителя; `a = 1` — формула из паспорта, `a = 0` — все города равноправны.

Высокое `H` — до города удобно добираться из многих городов, особенно крупных. Низкое — связи медленные или единственные.

## Структура

```
habindex/            пакет: index.py (формулы), data.py (загрузка и проверка), scenarios.py (сценарии, приоритеты),
                     sensitivity.py (устойчивость рейтинга), report.py (Excel, CSV, графики), cli.py
data/golden, demo    синтетические данные;  data/real — для данных организаторов
scenarios/*.json     сценарии изменения связи
scripts/             генератор демо-данных
tests/               28 автотестов (формулы, сценарии, данные, сквозной прогон)
outputs/golden|demo  готовые результаты
```

## Запуск

```
pip install -r requirements.txt
python -m unittest discover -s tests          # проверка (можно и pytest)
python -m habindex demo                        # пересчитать обе встроенные выборки
python -m habindex check --pairs P.csv --pop POP.csv
python -m habindex run   --pairs P.csv --pop POP.csv --scenarios scenarios/my.json --hub Казань --out outputs/real --label "данные организаторов"
```
Параметры модели: `--t-ref 6 --w-time 0.7 --exponent 1`.

### Сценарий (JSON)

```json
{"hub": "Казань", "scenarios": [
  {"name": "ЖД быстрее", "changes": [{"a": "Казань", "b": "Екатеринбург", "mode": "rail", "time_h": 5}]}
]}
```
`mode` — `auto` | `rail` | `air`; `time_h: null` убирает вид транспорта.

## Что на выходе

`habindex_results.xlsx` (листы: рейтинг, пары, сценарии, приоритеты, чувствительность, устойчивость, параметры), те же таблицы в CSV и графики `ranking.png`, `heatmap_S.png`, `scenarios.png`, `priorities.png`.

Три вида выводов:
1. **Рейтинг хабов** — где расположить пересадочный узел для данной выборки.
2. **Сценарии** — что изменится в `S` пары и в `H` города при заданных изменениях.
3. **Приоритеты** — какое типовое улучшение (ускорение на 25 %, +1 вид транспорта, новая связь) даёт наибольший прирост `H`; считается аналитически и проверено тестом против полного пересчёта.

## Как проверена работа

- числа учебного примера (84,43 / 85,61 / 46,25; сценарии 88,28 / 86,56 / 89,24) воспроизводятся автотестами и независимым ручным расчётом;
- свойства формулы: границы 0–100, монотонность по времени и числу видов, насыщение при `t ≤ 6 ч`, нет двойного учёта видов;
- проверка входных данных: дубли, нули, города без населения, неполный набор пар.

## Ограничения

Индекс не учитывает стоимость, частоту рейсов, расписание, пересадки, задержки, вместимость, сезонность; «есть вид транспорта» не значит «есть прямой ежедневный рейс».
Формула насыщается: при времени ≤ 6 ч и трёх видах транспорта все связи получают 100, различия между сильными связями пропадают.
Для малого числа городов рейтинг зависит от одного-двух крупных городов (при `a = 1`); смотрите лист «Устойчивость рейтинга».
Демо-выборка отражает допущения генератора (в частности, что прямая авиация идёт в основном через Москву и Санкт-Петербург), а не реальную сеть.
